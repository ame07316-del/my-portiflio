# ADR — برومبت 5: سياق UX واكتشاف المحتوى

## رحلة الزائر (أصحاب أعمال يبحثون عن مطور — **فرضية** لا حقيقة)

| المرحلة | ماذا يحتاج أن يفهم | أين يُجاب |
|---|---|---|
| الوصول (0–3 ث) | هل ده مطوّر محترف؟ | Hero: اسم + مسمى + مجسم تقني حي = إشارة قدرة فورية |
| التوجه (3–10 ث) | إيه تخصصه بالضبط؟ | شريط المهارات الثمانية المذكورة منه شخصيًا، بلا مستويات مختلَقة |
| الاستعراض | إيه دليل الشغل؟ | العجلة: مشروعَا عملاء **موثقان بمراجعة كود** + 5 تجارب معملية مُعلَّمة Lab بوضوح |
| التحقق | هل الكلام صادق؟ | دراسة الحالة: تقنيات من `package.json`، معمارية من الكود، **حدود صادقة** (Sandbox)، وتحذير ماجنتا للحقول الناقصة |
| التواصل | أوصله إزاي؟ | إيميل + واتساب + GitHub حقيقية مؤكدة منه |

## ما تحتاجه كل دراسة حالة — وما حالتها الآن

| العنصر | الحالة |
|---|---|
| الهدف | ✅ من وصف المشروع المؤكد |
| دور عمرو الدقيق | ⬜ **بانتظار تأكيده** — يُعرض كشارة «بانتظار التأكيد» لا كحقيقة |
| الميزات | ✅ موثقة (README/مراجعة كود) |
| التقنيات | ✅ من `package.json` حرفيًا |
| الصور + النص البديل | ⬜ بانتظار أصوله — الكارت يعمل نصيًا بدونها |
| الروابط | ✅ معاينة + مستودع للمشروعين |
| نتائج/أرقام | 🚫 **لا تُعرض**: لا أرقام مؤكدة ⇒ لا أرقام إطلاقًا |

## معلوم / فرضية / مطلوب

| معلوم مؤكد | فرضية | مطلوب من عمرو |
|---|---|---|

| مشروعان بمعاينات ومستودعات مدققة | — | اسم كامل/نبذة إن أراد |
| إيميل + واتساب + GitHub | — | — |

## رحلة عمرو داخل اللوحة
دخول ← ملخص يرى **تحذيرات النقص قبل أي نشر** ← تحرير بتبويبات لغة ← معاينة بالمسودات بجلسة ← نشر (بقاعدة in_progress وتحذير الترجمة) ← عند الندم: استعادة نسخة (الحالية تُحفظ أولًا).
نقاط الاحتكاك المعالجة: جلسة منتهية ⇒ رجوع فوري لشاشة الدخول برسالة؛ انقطاع شبكة ⇒ مؤشر حالة صريح؛ حذف صورة مستخدمة ⇒ رفض بقائمة المواضع.
